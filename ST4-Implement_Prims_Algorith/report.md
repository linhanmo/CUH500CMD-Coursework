# Standard Task 4 : Implement Prim's Algorithm

The implementation completes the provided skeleton by filling the inner relaxation loop of Prim’s algorithm. At each iteration, `minKey` selects the unvisited vertex with the smallest `key` value, which represents the cheapest known edge connecting that vertex to the growing MST. Once selected, the vertex is marked as visited, and for every adjacent unvisited vertex `v`, if the edge `(u, v)` has positive weight and is cheaper than the current `key[v]`, both `key[v]` and `parent[v]` are updated. This greedy choice is correct because Prim’s algorithm maintains the invariant that the partial tree is always a subset of some MST (Cormen et al., 2009). The algorithm runs in \(O(V^2)\) time with an adjacency matrix, since `minKey` scans all vertices on each of the \(V\) iterations and the relaxation loop also scans all \(V\) vertices. Space complexity is \(O(V^2)\) for the matrix and \(O(V)\) for the auxiliary arrays.

The output routines were restructured to match the required format. Instead of printing edges in the order produced by `parent`, the code collects all \(V-1\) edges into a list, sorts them by weight, and then prints them. This is a deliberate deviation from the skeleton’s original `printMST`, because the task’s expected output shows edges in ascending weight order rather than in parent-array order. The MST adjacency matrix is then built by placing each edge’s weight symmetrically into a zero matrix. This two-pass approach (collect, sort, print) is clearer than trying to interleave sorting with the Prim loop, and it keeps the algorithm itself unchanged.

The additional function `validateMST` uses a union-find structure to verify that the edges described by `parent` form a spanning tree: exactly \(V-1\) edges, no cycles, and all vertices connected. Union-find with path compression gives near-constant amortised time per operation, so validation runs in \(O(V \alpha(V))\), which is negligible compared with the \(O(V^2)\) construction. This function is valuable because it provides an independent check on the algorithm’s output; a bug in the relaxation loop could easily produce a disconnected or cyclic “tree” that still looks plausible in the printed output. The task’s suggestion to detect cycles within the MST is therefore well served by this design.

A critical limitation of the current representation is the use of `0` as the sentinel for “no edge.” If the graph contained an edge of weight `0`, the condition `self.graph[u][v] > 0` would ignore it, and the MST would be wrong. Similarly, negative edge weights are silently excluded. Prim’s algorithm itself works correctly with negative weights as long as the graph is undirected and connected, so the limitation is purely representational. A more robust design would use `None` or `float('inf')` for missing edges and check `is not None` instead of `> 0`. This is a meaningful trade-off: the zero-sentinel keeps the matrix compact and the code simple, which is appropriate for the teaching example, but it would need to be replaced in any production setting.

From an algorithmic perspective, the adjacency-matrix implementation is well suited to dense graphs but inefficient for sparse ones. An adjacency-list representation combined with a binary heap priority queue would reduce the running time to \(O(E \log V)\), which is asymptotically better when \(E \ll V^2\) (Sedgewick & Wayne, 2011). Kruskal’s algorithm with union-find is another alternative, running in \(O(E \log E)\) and often preferred when edges are already sorted or when the graph is sparse. For the five-vertex graph in this task, however, the matrix approach is perfectly adequate and keeps the code close to the supplied skeleton, which is an important consideration in an assessed exercise. The chosen design therefore balances algorithmic correctness, readability, and adherence to the provided structure.

# Standard Task 1 : Chinese New Year Gift-Exchange

The solution models the gift-exchange as a Constraint Satisfaction Problem (CSP) (Dechter, 2003). Variables are the six givers; domains are Python sets of eligible recipients. Static constraints filter self-gifts, family members, last year’s recipient, and reverse edges. Global constraints require a perfect matching and at least one non-reverse edge. The recursive search uses MRV ordering: at each level it selects the unassigned giver with the smallest domain. This fail-first heuristic is known to reduce search tree size significantly (Russell & Norvig, 2010). After each assignment, forward checking removes the used recipient from all remaining domains. The `propagate` function repeatedly forces any singleton domain, implements dynamic constraint propagation, and backtracks immediately if a domain becomes empty. This combines forward checking with singleton propagation, a standard technique in CSP solvers (Haralick & Elliott, 1980).

The code is elegant and compact. Using Python sets for domains makes union, intersection, and removal operations concise. The `propagate` function is particularly tight: a single `while` loop handles empty-domain detection, forced assignments, and propagation. However, this compactness introduces side effects: `propagate` mutates `assignments`, `used`, `domains`, and `flag` in place and returns them. This mixing of mutation and return values can be confusing, and it forces `search` to make deep copies before each recursive call. A more functional design would return new immutable state objects, improving testability and reducing bug risk. Nevertheless, for \(n=6\), the performance cost of copying is negligible. Readability is strong: names are descriptive, docstrings explain inputs and outputs, and `validate_solution` provides an independent check. An alternative Python design could use lists instead of sets for domains. Lists preserve order and allow indexing, but membership tests and removals are \(O(n)\) instead of \(O(1)\). For \(n=6\), the difference is trivial, but sets better express the mathematical notion of a domain and make forward checking cleaner. Another alternative is iterative backtracking with an explicit stack, which avoids recursion limits and makes state explicit. However, recursive code is shorter and more natural for this depth. A critical observation concerns the global flag. Because Rule 4 forbids reverse edges as hard constraints, every valid edge is non-reverse, so `flag` becomes true on the first assignment and the final flag check is redundant. If the instructor intended to allow reverse edges while requiring at least one non-reverse, Rule 4 should be removed. The code conservatively follows the pseudocode, but this redundancy is worth noting. Overall, the MRV + forward checking + singleton propagation design is justified: it is more powerful than naive backtracking, yet remains readable and appropriately simple for a small CSP.

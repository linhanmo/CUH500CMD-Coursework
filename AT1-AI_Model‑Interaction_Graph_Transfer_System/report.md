# ADVANCED TASK 1: AI Model‑Interaction Graph Transfer System

The system models an LLM inference pipeline as a directed weighted graph \(G=(V,E)\) with adjacency-list storage. Each node carries Transformer-specific metadata (model family, parameter count in billions, quantisation scheme, context window, framework, GPU, throughput, TTFT), and each edge carries inference-level metadata (transformation type, latency in milliseconds, payload size, confidence, token counts, cost per 1k tokens, sampling parameters, cache hit ratio). This design mirrors production model registries such as MLflow and KServe, where model cards and inference SLAs are attached to both endpoints and requests (Sculley et al., 2015). During my internship at China Telecom, I led a small team building the company's next-generation agent system, where a planner, a retriever, a tool executor, and a verifier each acted as a node in an implicit graph. That experience convinced me that agents fail not because any single model is weak but because the *edges* between components are underspecified—latency, confidence, and cost are exactly the three properties I most often wished were queryable at runtime. The adjacency list is preferred over a matrix because real pipelines are sparse: \(O(V+E)\) space and \(O(\deg^+(v))\) neighbour iteration match the access pattern of BFS and Dijkstra far better than an \(O(V^2)\) matrix (Cormen et al., 2009).

The path queries reflect three different business objectives. Lowest-latency routing minimises \(\sum \text{latency}_e\), directly relevant to interactive LLM serving where TTFT dominates user-perceived quality. Cost-optimal routing minimises \(\sum \text{cost}_e\), which matters at scale because inference cost scales with token throughput. Most-confident routing maximises \(\prod \text{confidence}_e\), which is subtle: the product is not directly additive, so the implementation applies the standard log-transform \(w_e = -\log c_e\) and runs Dijkstra on the transformed weights. This is the same trick used in probabilistic shortest-path problems (Cormen et al., 2009) and avoids floating-point underflow when many low-confidence edges are chained. Edges with \(c_e \le 0\) are explicitly rejected because \(\log 0\) is undefined; this is both a mathematical and semantic safeguard. In the China Telecom agent project, I repeatedly saw confidence collapse not because any single hop was unreliable but because the product of many mildly uncertain hops silently became negligible—exactly the failure mode the log-transform makes visible.

Top-K path enumeration uses Yen's algorithm, which repeatedly suppresses edges belonging to previously accepted paths and re-runs Dijkstra on the spur node (Yen, 1971). The complexity is \(O(k(V+E)\log V)\) for the edge-suppression variant implemented here, which is appropriate for \(k \ll V\). A limitation is that Yen's algorithm assumes non-negative weights; this holds for latency and cost, and for \(-\log c_e\) because \(c_e \in (0,1]\). The Pareto frontier over (latency, confidence) is computed by bounded DFS with dominance pruning. The frontier is deliberately bounded by `max_paths` because the number of simple paths can grow exponentially; bounded DFS is a pragmatic alternative to exact multi-objective shortest-path algorithms, which are generally NP-hard when the objectives are not separable (Ehrgott, 2005). In the demo graph, the direct path `STT → Summariser → Sentiment Classifier` (240 ms, confidence 0.8550) and the safety-filtered path `STT → Summariser → Safety Filter → Sentiment Classifier` (280 ms, confidence 0.8567) form a genuine trade-off: the extra hop buys a marginal confidence gain at a 17% latency premium. In the China Telecom deployment, this was precisely the sort of decision we had to expose to the orchestration layer; a hard-coded "always route through the safety filter" policy was worse than exposing the Pareto frontier and letting the caller decide based on the query's risk profile.

Serialisation uses JSON with explicit schema validation in `from_dict`. JSON is preferred over Pickle because Pickle is unsafe to deserialise from untrusted sources and is not cross-language; JSON is also the interchange format used by ONNX Runtime and KServe (Python Software Foundation, 2024). Schema versioning is separated from graph-state versioning: the former tracks the layout of the serialised document, the latter tracks content mutations. This distinction is essential in distributed settings where two replicas may share a schema but diverge in content. In the China Telecom project, this separation was the difference between a rolling upgrade that completed silently and one that silently corrupted the routing table.

The delta-based exchange mechanism records every mutation as a versioned operation and applies it idempotently: deltas with version \(\le\) the receiver's current version are discarded, which guarantees that replaying a batch does not corrupt state. This is a simplified form of operation-based CRDTs (Shapiro et al., 2011); the simplification is that conflicts are not resolved, only ordered. In a multi-writer scenario, a version vector or a true CRDT would be required, and this is an honest limitation to acknowledge. The demo confirms that the replica converges to the primary graph's state after applying two deltas and rejects an immediate replay, validating both convergence and idempotency.

Two further design choices merit comment. First, `remove_node` performs cascading edge deletion in \(O(V+E)\); without this, dangling edges would silently corrupt path queries. This was a bug I personally hit when first prototyping the agent graph at China Telecom—removing a deprecated tool node left edges pointing to a non-existent executor, and the resulting `KeyError` only surfaced several hops later. Second, the `AIGraph.from_dict` method bypasses `add_node`/`add_edge` to avoid re-recording deltas during deserialisation, which is a deliberate optimisation but means schema validation must be performed separately. Both choices trade some code purity for correctness and performance, and both are justified at this scale.

# Advanced Task 2: Visitor Route Optimisation at the China Museum Of The South China Sea Using Dijkstra's Algorithm

The completed `dijsktra` method follows the standard label-setting formulation of the shortest-path problem (Dijkstra, 1959). At each iteration, `findSmallestNode` scans the fixed-order array `unpoppedQ` and returns the index of the unreached node with the smallest tentative distance. That node is removed from `Q`, appended to `explored`, and its unvisited neighbours are relaxed by comparing `dist[u] + weight(u, v)` against the current `dist[v]`. If the new candidate is strictly smaller, both `dist[v]` and `previous[v]` are updated; otherwise the neighbour is appended to `ignored`, which is a useful diagnostic record of every relaxation attempt that failed to improve the current best. Because weights are non-negative, once a node is removed from `Q` its distance is final; this is the correctness guarantee that lets the algorithm terminate as soon as `end` is popped (Cormen et al., 2009).

For the museum graph, the algorithm returns `['O', 'A', 'B', 'D', 'T']` with cost 13, matching the analytical solution. The distance table confirms the classical O(V²) behaviour: each iteration performs one linear scan over the remaining nodes, and the `history` snapshot after each iteration makes the relaxation process auditable. In the custom telecom graph, the shortest route `S1 → S3 → S5 → S6 → S8 → S9` costs 19 and demonstrates that the same implementation scales to nine nodes and thirteen edges without modification. The reachability matrix is obtained by running Dijkstra from every node in turn, giving an all-pairs reachability view that, in both graphs, is fully populated because both graphs are connected.

The first additional function, `all_pairs_shortest_paths`, runs the same algorithm once per source and stores the resulting distance vectors in an \(N \times N\) matrix. Its complexity is \(O(V \cdot (V^2 + E)) = O(V^3 + VE)\), which is acceptable for the eight- and nine-node graphs here but would be impractical for a real museum with dozens of galleries. The second additional function, the relaxation-change tracker embedded in `dijsktra(..., track_relaxations=True)`, records every successful `(from, to, old, new)` tuple, making it possible to reconstruct exactly which edges shortened which distances and when. In my work as a team lead on the next-generation agent system at China Telecom, this kind of trace was essential when debugging routing policies: agent failures rarely came from a single wrong edge but from a chain of late relaxations that silently changed the preferred path. The `ignored` list plays a similar role here, flagging candidate edges that the algorithm considered but rejected.

Two design weaknesses deserve critical comment. First, the index-mapping scheme is fragile. `dist` and `previous` are indexed by position in `unpoppedQ`, which is derived from the insertion order of `self.edges`. If a node is added later, or if the dictionary iteration order changes, the mapping silently shifts and `getIndex` must recompute on every access. A dict-based representation such as `dist = {node: value}` would remove this hazard at the cost of slightly more verbose lookups. Second, the tie-breaking rule in `findSmallestNode` uses strict `<`, so when two nodes share the same tentative distance the one appearing earlier in `unpoppedQ` is chosen. This is deterministic but undocumented; in the museum graph it causes node `B` to be expanded before node `C`, which in turn determines the exact order of the `explored` list. The final shortest path is unaffected, but anyone reading the trace must know this rule to interpret the output correctly.

A more fundamental limitation is that the implementation assumes an undirected, static graph with strictly non-negative weights. Real museum routing often involves one-way galleries, timed-entry zones, and floor-change penalties that are not symmetric. A directed variant would require storing two weight dictionaries or a pair of adjacency lists. A* with a geometric heuristic (for example, straight-line distance to the exit) would reduce the number of expanded nodes compared with plain Dijkstra, at the cost of requiring an admissible heuristic (Hart et al., 1968). For a museum with a small number of galleries the current approach is preferable because it is simpler and the search space is already tiny; for a large multi-floor museum, the heuristic would become worthwhile.

Finally, the reachability matrix in both demos is fully populated, which makes it a less informative test than it could be. Adding a deliberately unreachable node — say, a restricted storage area — would exercise the `sys.maxsize` branch that currently never fires. This is a missed opportunity to demonstrate robustness rather than just correctness on a fully connected input.
